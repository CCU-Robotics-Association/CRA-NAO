# 阈值与判定说明

默认阈值位于 `nao_diag/config.py`，可用 `config.local.json` 覆盖。安全相关值必须落在下表硬范围内，否则程序会在连接机器人前拒绝启动。

| 项目 | 默认值 | 可配置硬范围 | 含义 |
|---|---:|---:|---|
| 电量预警 | 25% | 0–100% | 低电量不是电池损坏，只提示充电 |
| 运动最低电量 | 50% | 40–100% | 电池项目必须 PASS，且运动前会重新读取；低于此值不动作 |
| 关节温度预警 | 50°C | 35–55°C | 被动检查记 WARN；主动运动在达到此值时即阻止/中止 |
| 关节温度失败 | 60°C | 45–65°C | 被动温度检查记 FAIL；固件温度状态非零始终优先判故障 |
| 静态命令/实测预警 | 0.08 rad | 0.02–0.12 rad | 仅在已上刚度时评估 |
| 静态命令/实测失败 | 0.15 rad | 0.05–0.20 rad | 明显跟踪偏差 |
| 小幅运动目标误差 | 0.12 rad | 0.02–0.20 rad | 支架动作的工程初值 |
| 最小实测运动/配置幅度 | 45% | 20–90% | 防止命令已发送但关节基本未响应 |
| 关节测试刚度 | 0.35 | 0.10–0.50 | 先释放全身，再对单关节缓升；不会继承更高刚度 |
| 普通关节动作幅度 | 0.10 rad | 0.02–0.15 rad | 始终受实际关节限位和安全边距约束 |
| 行走距离 | 0.08 m | 0.03–0.20 m | 仅用于隔离、安全、有人看护的场地 |
| 行走步频比例 | 0.25 | 0.05–0.35 | `MaxStepFrequency` 的保守上限 |
| StandInit 绝对总承重下限 | 1.0 kg | 0.5–3.0 kg | 与模型质量比例下限取较大值 |
| StandInit 绝对单脚下限 | 0.5 kg | 0.2–2.0 kg | 与模型质量单脚比例下限取较大值 |
| 稳定总承重/模型质量下限 | 60% | 50–80% | `FSR 总量 >= 比例 × ALMotion.getMass("Body")` |
| 稳定总承重/模型质量上限 | 140% | 120–180% | 稳定采样超出此值视为 FSR 数据不合理；不用于落脚冲击瞬间 |
| 稳定单脚/模型质量下限 | 12% | 8–25% | 左右脚分别必须达到，避免单脚传感器全坏仍通过 |
| 动作中最低承重比例 | 25% | 10–50% | `wakeUp`/`rest` 过渡按模型质量、行走按站立基线计算，并同时保留 1.0 kg 绝对下限 |
| 行走最大倾角 | 0.35 rad | 0.20–0.45 rad | 行走监控的绝对倾角停止门槛；StandInit 另用更严的 0.20 rad |
| 相机平均亮度 | 5–250 | — | 排查近乎全黑/全白 |
| 相机亮度标准差 | ≥3 | — | 排查近乎常量帧 |
| 音频能量提升 | ≥150 或 ≥1.35 倍 | — | 机器人自身测试音的通路筛查值 |

运动门禁按诊断对象分类：明确的相机、音频、声纳、触摸、脚部碰撞开关和 LED 故障不会阻止关节测试，但仍使对应功能及整机验收失败；关节、电机、电池、温度、IMU、FSR、跌倒/碰撞保护以及无法分类的诊断结果始终阻止运动。

注意：

- 温度状态、`ALDiagnosis`、跌倒事件等机器人固件判定优先于本地数值阈值；`RobotIsFalling`/`robotHasFallen` 是事件，程序比较其 ALMemory 时间戳而不是把历史值当实时布尔状态；
- 声纳有效范围随 NAO 代际差异很大，交互测试统一选择约 0.40 m 的共同可测区；
- 普通 FSR 数据项目会保留八路原始值，不单凭总重量判断硬件损坏；行走安全门控会先确认 `Body` 模型质量处于 3–8 kg 的合理范围，再在 `wakeUp` 前后用连续样本检查总承重上下限和左右脚分别承重，并在动作中监控动态总承重；
- 安全配置还限制动作持续时间 0.5–3.0 秒、手部幅度 0.05–0.25、限位边距 0.05–0.40 rad、触摸等待 3–30 秒、相机帧率 1–15 FPS、远程日志 100–10000 行；
- 关节电流因关节类型、姿态和负载差异明显，默认记录而不使用全身统一安培阈值；
- 麦克风、相机和电池容量的严格阈值需要外部标准设备或标准工况；
- 正式批量验收前，用同型号、同固件的已知良机建立中位数和离散度基线。
